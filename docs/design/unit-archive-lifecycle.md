# Unit archive lifecycle

Archiving a unit removes it from day-to-day lists and new assignments. Managers can open it from the property's Archived Units view, review its history, and restore the same unit. The transition uses the existing `Unit.archivedAt` field and preserves the unit ID, name, leases, invoices, maintenance tickets, and notes. [Issue #95](https://github.com/parcelis/parcelis/issues/95)

## Proposed behavior

| Situation                                              | Behavior                                                                                                                                                                                                          |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Archive an operational unit                            | Require `units.archive` and confirmation. Set `archivedAt` once. Repeated requests return the current state and preserve the original timestamp.                                                                  |
| Unit has a scheduled, active, or notice lease          | Reject with `CONFLICT` and explain which lease states must be resolved. Use contractual status even if the lease is archived in the directory. The message should work for callers without lease-view permission. |
| Unit has drafts, ended leases, or existing receivables | Allow archive. Preserve drafts and their selections. Require an eligible selection when finalizing a draft. Keep billing and collections available under existing permissions.                                    |
| Restore an archived unit                               | Require `units.archive` and confirmation. Clear `archivedAt` and return the unit to operational views. If the parent property is archived, require restoring the property first.                                  |
| Permanently delete a unit                              | Require `units.delete`. Reject if any lease, maintenance association, or note exists. Invoices are linked through leases. Use Archive as the alternative in the conflict message.                                 |

The lease policy is proposed for properties, units, and tenants under [#320](https://github.com/parcelis/parcelis/issues/320). Coordinate the operational counts with [#317](https://github.com/parcelis/parcelis/issues/317). Keep archive/restore independent of the stored `Property.unitCount`. Derive any active inventory total from actual nonarchived unit rows and count occupied units only in that same inventory. Preserve visibility of historical receivables and previously assigned work.

## Implementation order

1. **Add the scoped lifecycle API.** In the app router, add `units.archive` and `units.reactivate` using `apiPermissionProcedure("units", "archive")` and the shared `unitByIdInputSchema`. Resolve the unit through its parent property's organization and return a scoped not-found error for missing or foreign IDs. In a transaction, check the current archive state and eligibility, write the transition, and return `{ id, archivedAt }`. Add REST wrappers for `PATCH /units/{id}/archive` and `POST /units/{id}/reactivate`, following the property routes. Signed-in users need `units.archive`. Organization API tokens can call allowlisted REST operations for their own organization. [App router](../../apps/api/src/router/app.router.ts) · [REST router](../../apps/api/src/router/public.router.ts) · [API token allowlist](../../apps/api/src/router/trpc.ts)

2. **Close write races and preserve history.** Do the archive eligibility check and the unit eligibility checks in lease assignment transactions. Cover `leases.createDraft`, `leases.updateDraft` when switching units, `leases.finalizeDraft`, `leases.create`, and `tenants.createLease`. A saved draft can still be opened and changed to an eligible unit. Use the existing serializable transaction pattern for interacting reads and writes, handle `P2034`, and verify on PostgreSQL that concurrent archive and lease completion cannot both succeed. Apply the coordinated #320 checks to parent property and tenant selections. Reject archived units on new maintenance assignments while preserving existing ticket associations during edits. Verify that competing note or ticket writes cannot gain a unit association that a concurrent hard delete then cascades away. Use transaction coordination with those writers if the existing guards are insufficient.

3. **Protect property unit synchronization before changing reads.** `properties.update` currently treats omitted unit IDs as deletions. Scope the permission checks, removal candidates, and delete query to operational units inside the transaction. Preserve archived rows omitted by the editor and return a conflict for archived IDs submitted by a stale editor. Have the web editor submit the active unit IDs it originally loaded and reject its save if that set changed. This also protects a unit restored after the editor opened. Keep the history guard shared across standalone delete and property-editor removals, and ensure property deletion still checks the history of all child units. Keep the existing per-property name uniqueness across archive states so the same unit can be restored under its original name.

4. **Separate operational inventory from history.** Extend [`listUnitsInputSchema`](../../packages/schemas/src/index.ts) with optional `archiveStatus: "active" | "archived" | "all"`, defaulting to active in the resolver. Filter nested inventory in `properties.list` and `properties.byId` as well. Keep lease, invoice, note, and ticket queries linked to archived units and match records by unit ID where available. Use `units.byId` to load the selected unit on its detail page and check that it belongs to the property in the URL. Load Archived Units with `units.list({ propertyId, archiveStatus: "archived" })`. Audit the property detail fallback that builds unit cards from `unitCount`, along with the directory and drawer placeholder generation, so archived units never reappear as synthetic vacancies. Keep a true zero-unit state.

5. **Wire up the UI.** On unit detail, reuse `EntityLifecycleControls` in the Actions menu and extend it to support a restore confirmation for units. Show an Archived badge and keep the manager on the detail page after either transition. Remove archived units from the active unit switcher, lease and maintenance pickers, and property editor. Put an Active Units / Archived Units switch on the property detail page with existing UI primitives. Where an existing maintenance ticket references an archived unit, keep that selection visible when editing the ticket. Invalidate property list/detail and unit list/detail queries so the switcher, selectors, and archived view reflect the new state. Surface permission and eligibility errors in the confirmation dialog and show a clear empty state when the selected list has no units. [Unit detail page](../../apps/web/app/%28authenticated%29/properties/%5Bid%5D/units/%5BunitId%5D/page.tsx) · [Shared lifecycle controls](../../apps/web/components/entity-lifecycle-controls.tsx)

6. **Update the companion documentation.** Update the Unit Details and Property Details guides on `docusaurus-docs-site` to cover archiving, finding and restoring archived units, and blocked archive/delete cases. Run `pnpm --filter @parcelis/api generate:openapi`, sync the resulting spec to `docusaurus-site/static/openapi/parcelis.openapi.json`, then run `pnpm --dir docusaurus-site generate:api` and `pnpm --dir docusaurus-site build` in the docs repository with its pinned pnpm version. Cross-link the application and docs PRs.

## Acceptance checks

- **Permissions and lifecycle.** Cover same-organization archive and restore, denied permissions, cross-organization IDs, the REST token allowlist, retry behavior, and restore under an archived parent.
- **Lease policy.** Cover scheduled, active, and notice leases, including a lease hidden by its own archive flag. Verify archive-after-draft, reselecting a unit, successful finalization after restore, and concurrent archive versus finalization on PostgreSQL.
- **Preservation.** Confirm that ended leases, invoices and balances, maintenance associations, and notes remain accessible after archive. Confirm that both standalone delete and property-editor removal reject units with history. Save a property after its last unit is archived and verify that the archived row survives.
- **Operational views.** Check list filters, a bookmarked archived unit, lease and maintenance pickers, property/dashboard counts, and loading, empty, and error states. Use Playwright to exercise Actions → Archive Unit → Archived Units → Restore Unit and verify the active list updates.
- **CI.** Run the API suite with `pnpm --filter @parcelis/api test`, the relevant package type checks and lint, the focused Playwright spec, and the docs build. For PostgreSQL coverage, follow the isolated database setup used by the existing lease integration suite.
